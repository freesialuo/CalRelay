# 来源管理前端（#89 / #77 第二阶段）

基于 #82 的唯一来源配置/OpenAPI契约，前端按稳定 source_id 读取分页摘要与详情，创建为禁用配置，编辑后显式启用/禁用，退休永久不可复活。ICS URL、ICS 手动配置、标准日历手动和 push-only producer 复用同一生成类型；本页面不上传文件、不抓取事件、不执行 producer，不配置规则/Bark/订阅或远端双向编辑。

## 已实现与尚待装配

`SourcesAPI` 从生成声明引用配置/记录/摘要/页类型，验证有界 HTTP 响应、ETag 与 config revision。创建只使用 If-None-Match: *，更新/退休只使用对应的 quoted If-Match；来源 revision 不作为配置写条件。服务端业务/能力校验仍为权威。日历既有 ID/external_id 只读，取消选择保留映射；新增映射以新稳定 ID 追加。

生产默认没有模拟登录：来源 GET 仍需要服务端管理身份/会话；未装配或拒绝不会显示为空实例。写入必须持有真实 POST session 返回的内存 csrf_token/write_nonce/expires_at；Cookie 本身不能恢复一次性写凭据。公开 Turnstile 配置、真实 widget/登录和生产 admin bootstrap 由认证/runtime owner 冻结后接入，当前尚未集成，因此不能把组件 fixture 的保存成功当作完整产品验收。

`AdminSession` 全局串行管理写入，发送前消耗本地 nonce，接到新的 X-Admin-Write-Nonce 才恢复后续写入；授权业务失败也读取轮换，缺失/相同 nonce、403、网络失败或取消不复用旧授权。并发登录拒绝重复派发，页面离开使旧回调不能重新装入已清除的授权。凭据仅私有内存字段，不存 DOM/storage/URL，不输出日志或分析。

## 失败与用户输入

- 保存成功只基于经验证的真实配置回执；不表示已抓取事件、重新规划或送达设备。
- CAS 冲突保留草稿，阻止覆盖；“读取最新版本”仅展示当前版本，必须显式采用才替换草稿与写条件。
- 写入取消/响应丢失为结果未知，不能当作撤回或自动重试；重新登录并读回当前来源后核实。
- 重复点击不能再发出写入。返回/离开需确认放弃未保存输入；刷新后只读服务端状态，不重放写请求。
- 静态与推送来源没有轮询字段；手动源没有 SLA，push-only SLA 可选。离线不是核心故障。
- 退休有明确二次确认；确认后禁用写操作，历史 record 可只读查询。

## 验证与边界

`npm test` 顺序运行生产构建烟测/管理会话操作测试和独立组件浏览器测试，继续由现有 frontend job/quality-gate 执行，不修改共享 workflow。`tests/fixture/sources.html` 是单独的测试入口，使用每次唯一的合成挑战，仅由 component test 的开发服务器提供；不是 production build input，不在生产默认路径启用。route fixtures 的可变记录只用于页面故障/竞争测试，不代表 SQLite 持久化。

当前自动覆盖：内存 nonce 轮换/拒绝/丢失/并发登录与写入；组件空列表→禁用创建→启用→编辑→退休→刷新；CAS 草稿/显式采用；403/409/422；取消写入结果未知且无重复请求；返回放弃确认；恶意名称只作文本；static/push 字段真实隐藏。有效 Red 包括403错误分类、并发登录派发次数2/预期1、static周期字段可见/预期隐藏，修复后通过。

真实管理 guard + HTTP + SQLite 浏览器集成、CSRF/Origin负例和公开挑战元数据/真实登录仍依赖认证 owner 的测试专用安全装配与公共契约。没有这些依赖不能关闭 #89，也不能宣称 #77/#35 完成。原 #81 基础证据见[管理前端](admin-web.md)。
